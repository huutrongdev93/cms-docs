## What this repo is

Docusaurus 3 documentation site for **SkillDo CMS** (a PHP CMS), written in **Vietnamese** (locale `vi`). This repo contains only docs — the actual CMS source code lives at:

```
E:\GoogleDriverData\projects\source.5.x\sourcev8
```

That source repo has its own CLAUDE.md. When writing or updating docs about CMS behavior (classes, namespaces, hooks, models, config…), verify against the real source there instead of guessing — recent doc work has been about syncing docs with the v8 source.

## Commands

```bash
npm start            # dev server with live reload
npm run build        # build static site into build/
npm run serve        # serve the built site
npm run clear        # clear Docusaurus cache (fix stale build issues)
```

No tests or linter. `npm run build` is the main validation step — `onBrokenLinks: 'throw'` makes the build fail on broken internal links, so run it after moving/renaming doc files.

Algolia search config reads `ALGOLIA_APP_ID`, `ALGOLIA_API_KEY`, `ALGOLIA_INDEX_NAME` from `.env` (gitignored). A missing `.env` may affect builds that touch the search config.

## Structure: four docs plugin instances

Configured in `docusaurus.config.js`, each with its own sidebar file and version state:

| Content dir | Route | Sidebar file | Content | Versioning |
|---|---|---|---|---|
| `docs/doc/` | `/8.0.0/...` (routeBasePath `/`) | `sidebars.js` | Core CMS documentation | current = 8.0.0; older 7.x snapshots in `versioned_docs/version-7.*` per `versions.json` |
| `devtool/doc/` | `/devtool/...` | `sidebars-devtool.js` | Docs for the **DevTool** plugin | current = 1.0.0 |
| `ecommerce/doc/` | `/ecommerce/...` | `sidebars-ecommerce.js` | Docs for the **sicommerce** plugin | current = 1.0.0 |
| `hooks/doc/` | `/hooks/...` | `sidebars-hooks.js` | Hook reference | current = 1.0.0 |

Key implications:

- **Edit the current (8.0.0) docs in `docs/doc/`**, not in `versioned_docs/` — those are frozen snapshots of 7.x releases. Only touch `versioned_docs/` when intentionally fixing an old version.
- All sidebars are `autogenerated` from the filesystem. Ordering is controlled by numeric filename/folder prefixes (`01-Prologue`, `02-Framework`, `06-Cms`, …). Renaming a file changes its URL slug — check for links pointing at it (build will throw if broken).
- Many folder/file names contain spaces (e.g. `docs/doc/09-Admin Development/05-Metabox Metadata.md`) — always quote paths in shell commands.
